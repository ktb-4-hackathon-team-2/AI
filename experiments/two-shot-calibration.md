# 2장 촬영 교차 뷰 캘리브레이션 — 실험 결과와 트레이드오프

> 결정용 문서. 실험 재현: `python experiments/two_shot_test.py`
> 자기 웹캠 사진으로 검증: `python experiments/two_shot_test.py --a 정면.jpg --b 실사용위치.jpg`

## 두 방식

| | **기존: 1장 + 3뷰 프리셋** (현재 구현) | **신규: 2장 + 자유 배치** (실험) |
|---|---|---|
| 촬영 | 실사용 위치에서 1장. 카메라는 정면/좌대각/우대각 중 택1, 해당 뷰 실루엣 가이드로 위치 강제 | ① 정면 실루엣으로 바른 자세 강제 → ② 실사용 위치(각도 제한 없음)에서 같은 자세 1장 |
| baseline | 그 1장의 2D 스켈레톤 | ②의 스켈레톤 (단, ①과 3D 특징 대조로 "정말 바른 자세인지" 검증 후 채택) |
| 모니터링 | baseline 대비 2D 편차 (변경 없음) | 동일 — 모니터링 로직은 두 방식 모두 그대로 |

핵심 차이는 **모니터링이 아니라 "baseline이 바른 자세임을 어떻게 보장하느냐"**다.

## 실험 결과 (experiments/two_shot_test.py)

**실험 1 — 2D 지표는 뷰를 넘지 못한다.** 정면에서 잡은 2D baseline을 그대로 다른
각도에 적용하면 같은 자세도 요 30°부터 오경보(score 1.02, 45°에서 2.23).
→ 교차 뷰 대조는 2D로 불가능, MediaPipe **월드 랜드마크(3D)** 기반 뷰 불변 특징이 필요.
(`app/core/view_invariant.py`: 목 굽힘각, 머리 전방/높이 비율, 좌우 기움각 — 몸 내부 기준계라 카메라 위치 무관)

**실험 2 — 단일 프레임은 부족, 20프레임 평균이면 충분.** 프레임당 노이즈(평면 1cm/깊이 3cm) 몬테카를로, 요 0~45° 교차:

| 촬영당 프레임 | 같은 자세 오거부 | 거북목 6cm 감지 | 심한 거북목 감지 | 옆 기움 감지 |
|---|---|---|---|---|
| 1프레임 | 3~5% | **19%** ← 실패 | 9~13% ← 실패 | 18~24% ← 실패 |
| **20프레임 평균 (1~2초)** | 3~4% | **~100%** | 96~98% | ~100% |

→ 신규 방식을 채택한다면 **촬영 버튼 = 1~2초 캡처 후 특징 평균**이 필수 구현 조건.
산정 허용 오차는 `view_invariant.DEFAULT_TOLERANCES`에 반영해 둠 (목 굽힘 ±9°, 머리 전방 ±0.075 등).

**실험 3 — 실사진 파이프라인 안정성.** 실제 사진의 크롭/스케일 변형 4종에서 특징 변화
최대 7.6°(목 굽힘) — 단일 프레임 노이즈 수준과 일치, 20프레임 평균 전제와 부합.

**한계**: 합성 실험은 프레임 간 독립 노이즈만 모델링. MediaPipe가 특정 각도에서 갖는
**체계적 편향**(예: 45° 이상에서 깊이 왜곡)은 실물로만 측정 가능 → 팀원 웹캠으로 CLI 검증 필요.
lite 모델 기준이므로, 캘리브레이션 순간만 full 모델을 쓰면 여유가 더 생김.

## 트레이드오프 정리

| 축 | 기존 (1장 + 3뷰) | 신규 (2장 + 자유 배치) |
|---|---|---|
| **카메라 배치** | 3개 프리셋 각도만 | 상반신만 보이면 어디든 (모니터 옆, 선반 위, 비스듬한 노트북 등) |
| **baseline 신뢰성** | 실루엣은 "위치"만 강제 — 그 순간 자세가 좋은지는 유저 양심에 의존. 대각 뷰 가이드는 fidelity 낮음 | 자세 검증이 가장 쉬운 정면에서 강제 + 3D 교차 검증으로 ②가 실제로 같은 바른 자세인지 확인 (거북목 6cm도 잡아냄) |
| **온보딩 UX** | 1단계, 30초 | 2단계 — 바른 자세를 유지/재현한 채 카메라를 옮겨야 함. 검증 실패 시 재촬영 루프(오거부 3~4%) |
| **기술 리스크** | 없음 (구현·검증 완료) | MediaPipe 월드 랜드마크 깊이 품질 의존. 20프레임 평균 필수. 실물 각도별 검증 미완 |
| **구현 비용** | 0 (완료) | 서버 +0.5일 (`/api/calibrate/pair` 엔드포인트 — 코어 모듈은 이미 작성됨), 프론트 온보딩 화면 수정 |
| **실패 모드** | 나쁜 자세로 캘리브레이션하면 그게 기준이 됨 (조용한 실패) | 검증 실패가 명시적으로 드러남 (시끄럽지만 안전한 실패) |

## 권장

- **데모 안정성이 최우선이면 기존 방식 유지** — 이미 e2e 검증 완료, 리스크 0.
- **"카메라 아무 데나 둬도 된다"를 셀링 포인트로 쓰려면 신규 방식** — 코어 모듈과
  허용 오차는 준비돼 있고, 남은 것은 ①20프레임 캡처 UX ②`/calibrate/pair` 엔드포인트
  ③팀원 웹캠 실물 검증 3가지.
- 절충안: 기존 3뷰 플로우를 기본으로 두고, 신규 방식을 "자유 배치(베타)" 옵션으로 추가.
  두 방식 모두 모니터링 로직은 공유하므로 병행 비용이 낮음.
